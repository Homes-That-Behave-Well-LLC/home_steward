# Reasoning and authority boundary

> Accepted HTBW non-authority restatement; new response/adapter details are proposed.

Knowledge is not authority. Access is not disclosure. Reasoning is not consent.
Recommendation is not authorization. An AI result is not permission to act.

## Proposed action path

Home Steward result/proposal -> responsible HTBW capability -> Operational Trust decision for this
request/context -> required human confirmation/escalation -> Concierge orchestration ->
authorized native executor -> observed result/Truth evidence -> existing Decision Trace.

Operational Trust decides permission; it is not the executor. Home Steward cannot grant its own
permissions or record an action as physically successful because an API accepted a request.

## Forbidden shortcuts

- Paying/transferring because a financial document was readable.
- Sending/replying/agreeing because mailbox access exists.
- Removing an obligation because a manual suggests a different interval.
- Changing Asset relationships because a model is confident.
- Exposing person-scoped information through a shared speaker.
- Running an MCP tool because it was enumerated.
- Treating previously similar actions as permanent consent.
- Turning a public/retrieved interpretation into current HTBW Truth.

Source content and tool results can contain malicious instructions. They never outrank policy,
authorization, provenance or explicit request scope.

The model may answer, refuse, identify uncertainty, ask for missing information or propose a step.
If permission is unavailable, the protected action is not performed; the explanation must be
audience-safe. Raw internal prompts/content need not be retained indefinitely for explainability.
