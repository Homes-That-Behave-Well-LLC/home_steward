# BehavesWell Extended Intelligence extension model

> Proposed canonical baseline; awaiting Owner acceptance. Inherits DL-131's non-regression boundary.

## 1. HTBW native capability

Available by its own accepted scope without BehavesWell Extended Intelligence: Asset identity/Type; Room/location,
ownership and document/manual/policy associations; owner/guest/insurance descriptions; maintenance
schedules and Stewardship obligations; current/historical Truth; Identity; Operational Trust;
Continuity; deterministic Home behavior; Decision Trace; explanation of HTBW decisions.

These are architectural guarantees of ownership, not a statement that all are implemented today.

<a id="2-home-steward-extended-capability"></a>
## 2. BehavesWell Extended Intelligence extended capability

Authorized unstructured retrieval, RAG-or-successor search, natural-language question answering,
summarization, cross-source synthesis, comparison, document interpretation, permitted public
research, pattern identification and conversational candidate-relationship discovery.

An enriched capability remains **HTBW-owned and enhanced by BehavesWell Extended Intelligence**. Original documents and their
identity/access/lifecycle are not reassigned.

<a id="3-home-steward-proposed-action"></a>
## 3. BehavesWell Extended Intelligence proposed action

An answer may propose an action or obligation change. Every proposal returns to the responsible
HTBW capability and Operational Trust, then an authorized executor if permitted.

Tool possession, credentials, data possession, model confidence, prior similar actions or an MCP
tool's presence confer no authority.

## Invocation test

If HTBW can answer authoritatively and cleanly without retrieval or reasoning, do not unnecessarily
invoke BehavesWell Extended Intelligence.

"Show the associated warranty" is native document capability. "Does the warranty cover this failure?"
may need authorized interpretation. "Schedule service" is an action requiring HTBW governance,
not a consequence of an AI answer.
