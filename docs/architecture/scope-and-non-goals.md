# Scope and non-goals

> Proposed canonical baseline; awaiting Owner acceptance. [Authority](../governance/authority-order.md).

## Current phase

Architecture, governance, fictional scenarios, vendor-neutral requirements and dated public-source
bootstrap notes. Five bootstrap/research issues (#1-#5), plus #6 for the DL-153 product-identity
transition; no candidate-per-issue expansion.

## In scope as requirements, not implementations

Governed retrieval/synthesis, separately authorized sources, private locality, derived-data lineage,
candidate relationships, action proposals, qualified commodity host platforms and future HTBW
integration boundary. Each requires its own review before runtime work.

## Not in scope

- A new Framework stage, a BehavesWell Core layer or Edition, or transferred BehavesWell Core ownership (DL-153).
- Authoritative Home state, person resolution, consent decisions, obligations, execution or Trace ownership.
- A new household conversational surface replacing Assist/Concierge.
- Inference/model selection, proprietary platform commitment or hardware purchase.
- Installing HA, MCP, model/RAG/vector/agent/inference/container/connector services.
- Runtime scaffolds, deployment, live benchmarks or ingestion of household content.
- Publishing private inquiry correspondence or claiming partnership/upstream acceptance.
- Completing #2-#5's qualification research/testing during bootstrap.
- Inventing a fine-grained information-category authorization taxonomy, deletion engine or universal retention.

The qualification profile is local-only by Owner direction. It does not rewrite DL-93's broader
permitted configured cloud-provider classes, the independent General Questions gate or its
Person -> Integration-default -> unavailable resolution.

Unresolved [questions](../governance/open-questions.md) stay visible; do not use a vendor feature as an answer.
