# Can we retire this custom HTBW implementation

> Proposed synthetic retirement review; no custom code, behavior or configuration is removed.
> Applies [HTBW Architecture Stewardship](../architecture/htbw-architecture-stewardship.md).

## 1. Household request

"Can this custom HTBW implementation now be retired in favor of Home Assistant-native functionality?"
Review exact accepted behavior/replacement, not merely an available native API.

## 2. Existing HTBW knowledge

Accepted outcomes/rationale/contracts, implementation/configuration/adoption history and acceptance;
Foundation identities, Truth Facts, Stewardship care, Continuity state and Decision Traces.

## 3. Authorized private retrieval

Minimum approved exact implementation, data/configuration/version, test/diagnostic/acceptance and
rollback references. Logs and private Owner records require separate scope; secrets are excluded.

## 4. Optional public research

Official release/integration/developer evidence starting with [HA's native development boundaries](https://contributors.home-assistant.io/core/).
Community demos/names cannot prove equivalent behavior; no private code uploads.

## 5. Home Steward synthesis

Native availability is necessary but insufficient. Analyze behavioral equivalence, authority,
data migration, configuration migration, failure/degradation, performance, diagnostics, Explainability/
Decision Trace, existing household adoption, rollback, tests, HA-DEV validation and Reference Home
lived validation. Preserve intentional beneficial behavior, manual controls, exceptions and histories.

State the expected household outcome. Simplification/benefit and reduced upkeep must be compared with
new dependency/privacy/support obligations. Incomplete official proof blocks migration advice. Retirement remains a
candidate until exact-version validation and attributable Owner acceptance of the replacement.

## 6. Provenance

Source/implementation location/version/commit/publication date, review date, effective/installed
HA version and GA/Labs/preview/deprecation/removal status; inferred equivalence is not Truth/acceptance.

## 7. Candidate relationships

Potential replaceable mechanism is not obsolete governance, accepted migration or a reopened
decision. Retained contracts remain authoritative.

## 8. Household confirmation

Confirm intended behavior/current use through eligible review; this is evidence, not permission
to remove code or acceptance of a replacement.

## 9. Governed durable relationship

Responsible owners govern any accepted migration/retirement/configuration records. Original decisions/
history remain intact; no Home Steward Ledger/ADR write or new acceptance store.

## 10. Proposed actions

Return a migration-review draft through HTBW/Operational Trust with rollback/recovery, relevant
unit/static/type/integration tests, HA-DEV, Reference Home lived validation and Owner acceptance
**before retirement**. Nothing executes in this scenario.

## 11. Prohibited autonomous actions

No code removal/replacement, decision reopening, Ledger/ADR edit, issue creation/closure, data/
configuration migration, automation/policy change, HA update/Labs enablement or upstream work.

## 12. HTBW authority

Foundation data/configuration; Truth Facts; Identity reviewer; Stewardship care; Continuity intent;
Operational Trust authorization; Concierge formulation/orchestration/Trace, not acceptance.

## 13. Privacy and locality

Minimum separately approved repository/data/Person/audience scope before local review.
Derived packages inherit source lifecycle; rollback never resurrects revoked permissions.

## 14. Unavailable / degraded behavior

Missing equivalent behavior, official proof, recoverability or lived acceptance yields
"I don't know whether retirement is safe". Keep custom/native operation unchanged; no guessed fallback.

## 15. Acceptance expectations

All thirteen analysis areas; governance versus mechanism explicit; rollback, HA-DEV, lived validation
and Owner acceptance required. No superseded logic retires before acceptance.

## 16. Open questions

Future comparison criteria, authorized migration owner and exact evidence/retirement mapping remain
open; no ingestion, migration, deployment or code-generation runtime.
