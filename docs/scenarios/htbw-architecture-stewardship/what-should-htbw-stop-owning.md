# What should HTBW stop owning

Status: CANONICAL SCENARIO

Developed-content maturity only; not Owner, runtime or architecture acceptance.

> Proposed synthetic mechanism review; no HTBW governance responsibility surrendered.
> Applies [HTBW Architecture Stewardship](../../architecture/htbw-architecture-stewardship.md).

## 1. Household request

"What responsibility or implementation detail should HTBW consider returning to Home Assistant?"
Separate retained governance from a potentially replaceable implementation mechanism.

## 2. Existing HTBW knowledge

Accepted responsibility contracts/rationale and implementation/configuration references; Foundation
model, Truth Facts/history, Stewardship care, Continuity context and authoritative Decision Traces.

## 3. Authorized private retrieval

Minimum approved compatibility/adapter/workaround/state/configuration/lifecycle and custom-integration
evidence. Separate repository/Person/private review scope; no unrestricted code or credentials.

## 4. Optional public research

Verify native mechanisms with [official HA developer documentation](https://contributors.home-assistant.io/core/)
and exact release/integration sources. Community inspiration/similar naming is not equivalent support.

## 5. Home Steward synthesis

Identify candidates in compatibility logic, adapters, workarounds, duplicated native state,
duplicated configuration, custom lifecycle management and custom integration behavior now native.
**HTBW governance responsibility != replaceable implementation mechanism.**

A native state entity is not automatically a Truth Fact, a native trace is not automatically the
governed Decision Trace, and a native setting is not authority to discard accepted policy/participation.
Compare retained outcomes/contracts, expected simplification, new obligation, privacy, performance and
degradation. "Keep governance; investigate replacing only the mechanism" or no action may be correct.

## 6. Provenance

Accepted rationale/source/commit/date; official version/publication/review/effective and installed
HA match; GA/Labs/preview/deprecation/removal. Inferred duplication is not Truth or obsolete status.

## 7. Candidate relationships

Possible replaceable implementation is a review candidate, not a responsibility transfer, reopened
decision or accepted retirement. Official gaps block migration recommendation.

## 8. Household confirmation

Eligible reviewer confirms required outcome/boundaries; this is evidence, not permission to weaken
governance, delete state or retire implementation.

## 9. Governed durable relationship

Existing owners retain authoritative records and histories. A human/HTBW governing process may review
the draft; Home Steward cannot alter Ledger/ADR/configuration or write acceptance.

## 10. Proposed actions

Return mechanism-comparison review through HTBW/Operational Trust with equivalence, rollback/recovery,
tests, HA-DEV/lived validation and Owner acceptance before code retirement.

## 11. Prohibited autonomous actions

No responsibility transfer, decision reopening, Ledger/ADR edit, issue creation/closure, code/state
removal, migration, automation/policy/configuration change, HA update/Labs enablement or upstream work.

## 12. HTBW authority

Foundation model; Truth Facts; Stewardship care; Identity reviewer; Continuity intent;
Operational Trust permission; Concierge orchestration/formulation/Trace, not universal ownership.

## 13. Privacy and locality

Minimized separately authorized repository/source/Person/audience access before local synthesis.
No raw history/secret duplication or private upload; derived evidence inherits lifecycle.

## 14. Unavailable / degraded behavior

Unverified native coverage, missing rationale or stale evidence yields "I don't know whether the
mechanism can be replaced". Preserve governance and native/custom operation.

## 15. Acceptance expectations

Seven mechanism classes considered; governance-versus-mechanism explicit. No technical primitive
causes responsibility surrender, decision amendment or retirement before acceptance.

## 16. Open questions

Future supported-mechanism comparison, owner review and migration tests remain open; no scanner,
ingestion, cleanup bot, state migration or autonomous contribution.
