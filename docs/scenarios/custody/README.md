# Custody

Navigation and scope guidance only; not an architecture contract or roadmap. Browse the [scenario-family map](../README.md).

## Purpose

Understand authorized evidence around loans, exhibitions, transport, off-site care and return. Capture enrichment questions without duplicating HTBW's already-governed accountability lifecycle.

## Relationship to HTBW

Stewardship owns Custody Periods, Check-Out, Check-In, expected return, due/overdue obligations, reminders, history and period-scoped insurance responsibility; Foundation defines the existing type and relationships. Truth owns current location. See the existing [HTBW boundary](../../architecture/htbw-boundary.md).

## Possible Home Steward extension

Interpret authorized agreements, correspondence, environmental reports and condition evidence in the context of existing custody records. Any new source admission, representation, handoff or implementation is an OPEN ARCHITECTURAL QUESTION.

## Boundaries

Physical return is not recorded Check-In; declared custody location is not current Truth. Custody, ownership, caretaking and insurance are distinct. Never fabricate missing chain legs, create a shadow custody lifecycle, infer a new Counterparty object, or change reminders or insurance state.

Person/source/purpose/namespace/audience scope, household-controlled locality and source-derived lifecycle remain independent requirements. Potential evidence is not admitted access; knowledge is not action or disclosure authority. Source reports and inference are not automatic Truth; unknown is valid and correlation is not causation.
