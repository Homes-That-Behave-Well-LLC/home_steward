# Counterfactual and Planning

Navigation and scope guidance only; not an architecture contract or roadmap. Browse the [scenario-family map](../README.md).

## Purpose

Explore conditional consequences of possible changes using known dependencies and explicit assumptions, without claiming perfect prediction.

## Relationship to HTBW

Actual configuration, Truth, relationships, obligations and acceptance stay HTBW-owned. A hypothetical state is never current Truth or an approved change. See the existing [HTBW boundary](../../architecture/htbw-boundary.md).

## Possible Home Steward extension

Explain supported dependency, locality, care and source-lifecycle implications of a hypothetical change. Any new source admission, representation, handoff or implementation is an OPEN ARCHITECTURAL QUESTION.

## Boundaries

No removal, substitution, relocation, revocation, purchasing or policy action follows from a question. Missing dependencies remain missing; independence, export and restoration claims need evidence.

Person/source/purpose/namespace/audience scope, household-controlled locality and source-derived lifecycle remain independent requirements. Potential evidence is not admitted access; knowledge is not action or disclosure authority. Source reports and inference are not automatic Truth; unknown is valid and correlation is not causation.

## Reference Home discovery increment

Local is not automatically better; no local label or preferred vendor overrides declared outcomes, privacy, maintenance, recoverability or actual evidence. Historical blocker removal is not governance approval. Alexa, Ring and UniFi are contextual examples, not selected integrations. No migration, platform requirements, qualification or Issues #2-#5 work is introduced.

New primary files in this increment: **5**. Each is catalogued only in this primary family. All earlier bodies and maturity remain unchanged.

- [Which Ring capabilities have a local UniFi equivalent?](which-ring-capabilities-have-a-local-unifi-equivalent.md) — **VISION — NOT YET ARCHITECTED**. A Ring function and a similarly described UniFi function may differ in accessibility, privacy, reliability or care burden. The household wants candidate equivalence examined against actual declared outcomes, not vendor preference or a promise that local replacement is automatically better. A product feature description is not evidence of Reference Home equivalence.
- [Which historical data may be lost during migration?](which-historical-data-may-be-lost-during-migration.md) — **VISION — NOT YET ARCHITECTED**. A migration can leave useful service, device or household history in the former provider even if current controls are replaced. The household wants possible loss, lawful retention limits and unknown exportability understood without copying private data automatically. A local summary is not a substitute for revoked source authority or a complete historical export.
- [Which cloud dependency remains justified despite the privacy cost?](which-cloud-dependency-remains-justified-despite-the-privacy-cost.md) — **VISION — NOT YET ARCHITECTED**. A household may deliberately retain a cloud dependency because an important care, accessibility or familiar experience is not adequately preserved elsewhere. The household wants that declared tradeoff examined without a model deciding privacy is worth less or more than another outcome. A local alternative can add obligations or deliver a worse experience.
- [Which cloud dependency exists only because a local alternative was unavailable when the capability was created?](which-cloud-dependency-exists-only-because-a-local-alternative-was-unavailable-when-the-capability-was-created.md) — **VISION — NOT YET ARCHITECTED**. A cloud dependency may reflect an earlier technical limitation rather than an enduring household preference. The household wants its recorded reason distinguished from a convenient retrospective explanation. A later local option does not automatically remove the original governance concern or justify changing a capability the household still values.
- [Which local replacement introduces a new single point of failure?](which-local-replacement-introduces-a-new-single-point-of-failure.md) — **VISION — NOT YET ARCHITECTED**. Moving a capability locally can concentrate formerly separate outcomes on one appliance, operator or service. The household wants that candidate failure concentration and documented alternatives understood without assuming fewer outside services means greater resilience. Missing relationships or untested fallbacks must not be treated as zero risk.
