# Did this release create new risk or Technical Debt

> Proposed synthetic applicability review; no asserted HTBW failure or newly created obligation.
> Applies [discovery](../architecture/possibility-and-improvement-discovery.md) and [architecture stewardship](../architecture/htbw-architecture-stewardship.md).

## 1. Household request

"Did this release create any new risk or Technical Debt for us?" Distinguish observed current
failure from a future compatibility/migration/support obligation.

## 2. Existing HTBW knowledge

Foundation dependencies/custom/native configuration; current Repairs and accepted outcomes;
Truth current/Historical Facts, native Decision Traces and Stewardship existing obligations.

## 3. Authorized private retrieval

Minimum eligible version/API dependency, custom integration/change/acceptance and known debt evidence.
Logs/history require separate grants; do not assume an announced API appears in actual code.

## 4. Optional public research

[Official developer announcements](https://contributors.home-assistant.io/blog/) and exact release/
integration evidence. [Undefined helpers](https://contributors.home-assistant.io/blog/2026/11/01/undefined-helper/)
are announced November 1 but deprecated as of 2026.12; no removal date stated there.

## 5. Home Steward synthesis

Evaluate deprecations, changed APIs, unsupported behaviors, custom integration risk, duplicated
functionality, changed device semantics, stated future removals, migration obligations and new
dependencies. Check actual affected use before claiming risk; unaffected paths may need no action.

An announcement effective in a later release can create a future review obligation, not evidence
of current failure. Missing removal date remains unknown. Technical Debt is an assessment lens and
existing notes, not a new accepted model/responsibility. Give outcome, expected benefit/new burden and
bounded review recommendation; no compulsory migration.

## 6. Provenance

Source/version/publication/commit/review, effective and installed version, GA/Labs/preview/deprecated/
removal status, affected references and gaps. Pattern/hypothesis is not a Truth diagnosis.

## 7. Candidate relationships

Possible future incompatibility is a candidate; current failure needs actual eligible outcome evidence.
Similar API names or dates do not prove code dependence or causation.

## 8. Household confirmation

Confirm current outcome/support priorities; this is evidence, not acceptance of risk, migration
permission or authorization to waive an obligation.

## 9. Governed durable relationship

Responsible configuration/care/authority owners evaluate changes; no Debt registry, rewritten trace,
new obligation, issue edit or decision amendment by Home Steward.

## 10. Proposed actions

Offer HTBW/Operational Trust review with impact, maintainer/new obligation, manual fallback,
reversibility/rollback and acceptance tests; incomplete official evidence blocks migration advice.

## 11. Prohibited autonomous actions

No automation/scripts, dependency/code/configuration/policy/preference/obligation changes, HA update/
rollback, Labs/integration/entity enablement, issue closure or autonomous upstream work.

## 12. HTBW authority

Foundation dependencies; Truth Facts; Stewardship care; Identity requester; Continuity context;
Operational Trust permission; Concierge formulation/coordination/Trace.

## 13. Privacy and locality

Minimum authorized code/source/Person/audience scope; no secret/log uploads. Local derived risk
interpretations inherit lifecycle; no indefinite source memory or people ranking.

## 14. Unavailable / degraded behavior

Unknown dependency/version or stale official evidence yields "I don't know whether this affects us".
Do not infer current failure; preserve native operation without hidden fallback.

## 15. Acceptance expectations

All nine risk factors considered; future obligation/current failure and announcement/effective/removal
dates distinct. No unsupported diagnosis, new debt model or automatic change.

## 16. Open questions

Exact dependency proof, obligation review and future evidence retention remain open; no watcher,
log ingestion, code migration or debt engine.
