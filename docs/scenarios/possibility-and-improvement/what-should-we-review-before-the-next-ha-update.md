# What should we review before the next HA update

Status: CANONICAL SCENARIO

Developed-content maturity only; not Owner, runtime or architecture acceptance.

> Proposed synthetic pre-update review; no actual installed-version inspection or upgrade.
> Applies [Possibility and Improvement Discovery](../../architecture/possibility-and-improvement-discovery.md).

## 1. Household request

"What should we look at before installing this Home Assistant update?" Resolve actual installed and
candidate versions, eligible configuration and the intended review scope.

## 2. Existing HTBW knowledge

Foundation integration/device/capability dependencies; current Repairs/accepted outcome references;
Stewardship care; Truth Facts/history; native Decision Traces and eligible technical-debt notes.

## 3. Authorized private retrieval

Minimum installed integration/HTBW dependency versions, regression-sensitive requirements, Repairs,
change/acceptance and backup/recovery evidence. Logs/history need separate grants; no secret extraction.

## 4. Optional public research

Use [official release documentation](https://www.home-assistant.io/blog/categories/core/), developer/
breaking-change/deprecation sources and [native backup guidance](https://www.home-assistant.io/integrations/backup/).
No private configuration or logs sent to public research.

## 5. Home Steward synthesis

Produce applicable changes, non-applicable changes, things to verify, regression-sensitive capabilities,
backup/recovery prerequisites and post-update acceptance tests. Compare actual installed integrations/
HTBW dependencies with official relevant developer changes, current Repairs and known technical debt.

For example, naming changes can warrant checking native names versus retained household vocabulary,
not rewriting terms. A verified backup must cover relevant external/configuration/permission artifacts;
backup existence alone is not proven recovery. Separate opportunity from risk and Labs/preview from
standard support. State the expected household outcome for each recommendation, alongside benefit,
new obligation and unknown applicability.

## 6. Provenance

Exact installed/candidate version, source/publication/review/effective dates, GA/Labs/preview/
deprecation/removal state and scoped dependency/acceptance references. Inference is not current Truth.

## 7. Candidate relationships

Potential release-to-dependency regression is a review candidate, not current failure, root cause
or permission to install. Non-applicable items need adequate configuration evidence.

## 8. Household confirmation

Confirm intended outcome/window with an eligible participant; agreement to a review is not update
authorization, downtime consent or acceptance of post-update behavior.

## 9. Governed durable relationship

Responsible owners retain configuration/acceptance/care records and history. Home Steward's checklist
is a draft, not a new update/migration authority or acceptance store.

## 10. Proposed actions

Return verification/acceptance-plan proposals through HTBW/Operational Trust, with rollback,
recovery, manual fallback, new obligation and separately governed exact-version validation.

## 11. Prohibited autonomous actions

No HA installation/update/rollback/restart, configuration/policy/preference/obligation edit,
automation/scripts, Labs/entity/integration enablement or autonomous upstream contribution.

## 12. HTBW authority

Foundation dependencies; Truth Facts; Stewardship care; Identity requester; Continuity context;
Operational Trust permission; Concierge formulation/coordination/Trace, not acceptance.

## 13. Privacy and locality

Minimal approved source/Person/purpose/audience evidence; recovery credentials remain protected.
Local derived checklists inherit lifecycle; no raw-log memory or broad private backup read.

## 14. Unavailable / degraded behavior

Unknown installed version, stale docs or missing recovery evidence yields "I don't know whether this
update is ready for review". Do not invent a green light; native operation remains unchanged.

## 15. Acceptance expectations

All six output groups, applicable/non-applicable evidence and recovery/regression tests explicit.
No update, configuration change, Labs enablement or runtime acceptance is performed.

## 16. Open questions

Future source review, exact dependency inventory and update-acceptance mapping remain open;
no watcher, ingestion, backup execution or upgrade workflow.
