# Did Home Assistant create a new obligation for HTBW

> Proposed synthetic obligation review; no actual compatibility failure or new care record.
> Applies [HTBW Architecture Stewardship](../architecture/htbw-architecture-stewardship.md).

## 1. Household request

"Did this Home Assistant release create a new migration, testing, compatibility or support obligation
for HTBW?" Establish release/effective version and actual affected dependency.

## 2. Existing HTBW knowledge

Accepted architecture/implementation/tests, configured dependency versions, scoped issue/acceptance
references; Truth Facts, Stewardship existing obligations and native Decision Traces.

## 3. Authorized private retrieval

Minimum approved API/use/version/configuration/test and support evidence. Repository/private Owner
records and logs/history require separate grants; never assume an announced API is used.

## 4. Optional public research

[Official developer blog](https://contributors.home-assistant.io/blog/), release/integration/quality
documentation. [Undefined helpers](https://contributors.home-assistant.io/blog/2026/11/01/undefined-helper/)
are deprecated as of 2026.12, not a proved current 2026.11 failure; removal date unspecified there.

## 5. Home Steward synthesis

Evaluate deprecated API, changed entity/device semantics, config-entry behavior, conversation/LLM
interface, integration quality rule, security requirement, test/lint/type requirement and stated
future removal. Identify applicability and required evidence before asserting an obligation.

**Current failure != future obligation.** A later effective deprecation may justify planning/testing
while current behavior works; a published date alone does not prove incompatibility. State expected
outcome, maintainer/new burden, deadline or unknown deadline and dependencies. Technical Debt remains
an assessment lens; Home Steward does not create Stewardship records or invent migration urgency.

## 6. Provenance

Source URL/repository/version/commit/publication date, review date, installed/effective HA version,
GA/Labs/preview/deprecated/removal status and actual use evidence. Hypothesis is not Truth.

## 7. Candidate relationships

Possible change-to-future-obligation relevance is a review candidate, not current failure, an
accepted obligation or obsolete decision. Official evidence gaps block migration advice.

## 8. Household confirmation

Eligible reviewer confirms supported outcome and context; confirmation is evidence, not permission
to update, waive care, alter policy or accept a migration.

## 9. Governed durable relationship

Stewardship/other responsible owners evaluate obligations and records; accepted architecture/history
stays intact. No new Debt store, Ledger/ADR edit, issue mutation or acceptance write.

## 10. Proposed actions

Offer human-governed HTBW/Operational Trust review with impact, rollback, applicable unit/static/type
tests, HA-DEV/lived validation and Owner acceptance before any replacement retirement.

## 11. Prohibited autonomous actions

No obligation/code/configuration/policy change, decision reopening, Ledger/ADR edit, issue create/
close, migration, automation/script changes, HA update/Labs enablement or upstream contribution.

## 12. HTBW authority

Foundation dependencies; Truth Facts; Stewardship care; Identity reviewer; Continuity context;
Operational Trust permission; Concierge formulation/orchestration/Trace.

## 13. Privacy and locality

Minimum separately approved code/source/Person/audience evidence; protected data never enters public
queries. Local derived reviews inherit lifecycle, not universal ingestion or disclosure permission.

## 14. Unavailable / degraded behavior

Missing actual use/version or stale official source yields "I don't know whether this creates an
obligation". Retain native/custom operation; no guessed failure, deadline or cloud fallback.

## 15. Acceptance expectations

All eight potential findings; publication/effect/removal and current failure/future obligation
separate. No obligation, accepted decision, code or issue is automatically changed.

## 16. Open questions

Future applicable-use proof, governed support/deadline review and exact acceptance mapping remain
open; no watcher, log/repository ingestion, migration or testing runtime.
