# Host platform requirements

> Proposed canonical requirements; acceptance belongs to [#2](https://github.com/Homes-That-Behave-Well-LLC/home_steward/issues/2).

No hardware/provider/model is selected. Host features may be composed across governed local services.

## Mandatory boundaries

- Household-controlled local inference/storage and enforceable scoped egress.
- Routine local use without compulsory cloud account/service/subscription; transparent update/support behavior.
- Documented authenticated APIs and least-privilege person/source/application scope.
- Source/derived governance, bounded retention, provenance, export, correction, erasure and restore behavior.
- No self-granted execution authority, automatic Truth promotion or silent cloud fallback.
- Replaceability and meaningful offline/vendor-exit usability.

## Capability evaluation

Model capacity/quantization/concurrency; text/context/structured outputs; inference endpoint type;
embeddings; retrieval; parsing/OCR; file formats; image/audio support where needed; tools/MCP;
memory lifecycle; adapters; administration/health; 24x7 stability; thermals/noise/power; network
connectivity; updates/security; backup/recovery; ownership/license/support.

Home Steward should reuse commodity platform components, not build a bespoke generic AI stack.
No candidate receives credit for undocumented or assumed APIs. Hardware benchmarks do not prove RAG,
policy enforcement or a complete household intelligence platform.

## Cost and operation

Compare acquisition, upgrades, storage/backups, power, subscriptions/services, maintenance,
integration work, security/monitoring, restore exercises, support and disposal over five years.
Owner time is not free: record hours and an explicit valuation separately from cash cost.
Development-inference benchmarks are a separate workload from household knowledge quality.
