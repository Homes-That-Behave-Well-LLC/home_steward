# Contributing

This repository is in architecture/research phase. New proposals await Owner review; accepted HTBW
authority is not changed by a pull request, example, implementation or vendor claim.

1. Read the [authority order](docs/governance/authority-order.md) and [open questions](docs/governance/open-questions.md).
2. Extend one of the existing issues (#1-#5 bootstrap/research; #6 product identity); do not create a candidate-per-issue backlog during bootstrap.
3. Distinguish accepted authority, Owner direction, proposal, research, inference and unknown.
4. Cite dated official sources first. Summarize in your own words; do not copy manuals or copyrighted corpora.
5. Use synthetic scenarios. Do not submit source credentials, recordings, financial/health records,
   private correspondence, household inventories or device/account identifiers.
6. Keep source/person/privacy/locality and action boundaries explicit. A prompt is not an access-control system.
7. Update the document register and relative navigation with any document change.
8. Validate Markdown links, registered inventory, status language and citations. Documentation-only work
   does not require installing a runtime, linter or test dependency.
9. No runtime/install/deployment or issue closure without separately authorized work and review.
10. Use the product name **BehavesWell Extended Intelligence** in new and current documents (formerly
    Home Steward; HTBW DL-153). Never put © in a filename, path, identifier, URL or anchor, and do not
    rename `home_steward`/`home-steward` identifiers or paths without a governed compatibility plan. See
    [product identity](docs/architecture/product-identity-and-compatibility-boundary.md).

Future executable HTBW-connected work must preserve Windows authoritative Git/PowerShell, external
WSL test-only HA harness, both validation gates and exact-commit Windows HA-DEV deployment with
separate Owner acceptance. WSL must not host HA or deploy.

All rights remain reserved pending explicit licensing. Do not assume a contribution implies an
unpublished license or agreement; clarify contribution/licensing terms with the repository Owner.
